# CP035 — independent critique / limits

- CP035 does **not** run SQL. A mock checks that every `findOne`/`findAll` gets the same transaction *object*, not whether SQL grants, isolation, rollback, or lock ordering are correct. In one scenario, the fake ORM returns a foreign-owned row despite a WHERE clause; the unchanged CP034 candidate correctly rejects it and the bundle discards all partial output. In another, a foreign home is filtered by WHERE and the subject legitimately sees `home:null`, without chest or garden.
- `readPortalSectionsForServer` is not an authorization provider. It accepts `actor` and `transaction` from its caller, which MUST resolve the subject from a verified session and restrict the database principal to `SELECT`. It does not accept URLs, home IDs, apartment IDs or guild selectors.
- CP033 native growth calculations are time-based; the native `isReady`/`getGrowthProgress` call `Date.now()` independently, so the bundle's `now` argument is **not** a fully shared clock or proof of an atomic snapshot. Property uses `now`; other families can legitimately tick during request. REPEATABLE READ must be proved, not inferred from a shared object reference.
- The CP034 `canClaim` value mirrors the native notary snapshot but never authorizes a claim. Global remote property read is a **proposed product policy**, not a confirmed Core action. CP018 pantry derives guild from server-side player.guildId; guild membership data integrity and cache invalidation remain unproven.
- No automatic initialization: missing garden slots/storage/seed or chest rows return `not_initialized`, not fabricated empty inventories. A missing talisman row is also not created. Existing Core commands may create data on entry; this readonly surface intentionally does not.
- The bundle returns only selected sections and fails all sections if a reader throws or returns `unavailable`. There is no granular failure telemetry, pagination, quotas, retry strategy or HTTP response contract here. Large returned collections remain a memory/resource risk until transport limits are designed.
- Still no strict native upstream TypeScript build. Runtime transpilation confirms syntax and the candidates' local suites only; native imports and Core dependency graph require a pinned checkout with dependencies.
- Previous CP035 integration test draft had two invalid test assumptions: a mock SQL WHERE cannot return a wrong-owner home by default, and `Object.create(null)` is not an ORM mutation. Both were corrected in the final 15-test suite, including a separate intentionally bad adapter case. The draft 11/13 is not counted as a passing gate.
- Do not present CP035 as beta, deployable, linked to WA, production, or a visually approved site. CP032 art has not been approved.
